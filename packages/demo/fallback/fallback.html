Your exobrain, for you, forever.

Local, open-source agent memory and runner that gets stuff done so you can think.

In the box

01Self-hosted agent memory, structured-database-based for high recall.Memory is a local SQLite store of entities, append-only notes that each cite the raw message or file they came from, and work items. In the runner, each turn starts with prefetched context from a full-text search fused across memory, your configured sources and past chats, plus pages derived per entity from the notes, so recall comes from structure and citations.

Every row carries the scopes allowed to read it, and two ids for one thing (your "Dana" and a shared "Dana Okafor") can be linked for reads and unlinked later. A push plane fills the store from your sources through a model you configure, under a daily dollar budget. Each entity's page is derived from the notes you can read. Search is full text with rank fusion, not embeddings. tophat graph draws the store as the graph below, and tophat-mcp lets any agent harness read and write the same memory.

Recall, measured

Two tests of recall. Each bar is questions answered correctly out of the total; every memory system gets the same answering model and judge, and the chat-assistant services answer with their own models. On the 99 personal questions tophat answers 96, level with putting the whole haystack in the prompt; on the 15 hardest LongMemEval-S questions it answers 8, against 9 for all in context (baseline).

02Polished agent runner and chat interface, with a million little QoL features.Each conversation is its own agent process with memory tools, subagents, goals, waits and a browser tool, and the chat app streams replies, thinking and tool calls as they happen. You can send while it works, a restart hands chats over instead of ending them, and the sidebar doubles as an inbox where automated arrivals open their own chats.
  • Subagents: a fresh model conversation with its own tools and budget, six at once, checking in with the parent every 180 s while they run.
  • Goals and waits: a turn with open goal items is handed back to the agent, and a blocker that changes with time becomes a wait with a retry time that wakes the chat.
  • Select text for Quote, Sidechat and Fork; side threads sit in a rail beside the transcript.
  • Images, video, audio, HTML widgets, KaTeX math and code render in the transcript; chats can be incognito, shared by link, or open to several clients at once.
  • A reader for articles, EPUB and PDF with highlights, a synced notes editor, a password vault the browser tool fills from without the value entering the transcript, and an offline-capable PWA.
03MacOS computer use, including Contacts, iMessage, FindMy, Shortcuts, and Apple Home.Contacts, Calendar, Notes, call history, photo metadata and iMessage (read only) ship in the public repo, along with browser control and a hook for a computer-use server. Find My, Shortcuts and Apple Home are in the full system and not in the public repo yet.

Contacts, Calendar and Notes go through a signed helper app that owns the macOS privacy grants; call history, photo metadata and iMessage need Full Disk Access. The public repo reads mail and messages and does not send them. The browser tool leases a Chrome tab, yours or an isolated one, through a loopback DevTools endpoint. The agent runs shell commands without a confirmation step; tophat setup confines its file tools to the instance workspace, not the shell. macOS is the strongest platform.

04Connectors enough to capture full context, including location, screen recording, and all-day audio.Sources poll Gmail, IMAP, iMessage, Beeper, Apple apps and REST APIs, and take records through a file drop and a webhook, so each record enters memory with its source attached and is deduplicated by source, account and id. Continuous capture such as location, screen recording and all-day audio is in the full system, and the public repo gives you the adapter interface, file drop and webhook to feed in your own.

The runner owns each source's cursor and commits it only after the store has the records, and one broken source never stops the rest. Each source's text goes to your model provider during derivation, so enable them one at a time; a private-people blocklist keeps chosen people's message bodies away from the model. With wakes on, the intake model decides which new arrivals need you and posts them into the owning chat as an automated event.

05Per-memory e2ee p2p sharing for collaborative projects.Each note is sealed under its own fresh AES-256-GCM key, and that key is wrapped to the groups allowed to read it, so access is per note rather than per account or folder. Replicas on each person's devices sync through a hub that stores only ciphertext and can open none of it; share widens one note to a group and retract takes it back.

To join a shared scope the hub operator gives your device a token, you sync, the scope's admin adds you and syncs, and you sync again to receive its rows. Removing a member rotates the scope key. Derived pages are reused across members only when each can read every note behind them. Sync is optional and off by default. The hub operator issues device tokens, so against a hub you do not run you trust the operator not to mint devices; run your own if that matters. Team use is early.

06All local, private, fully customizable, and open-source.Everything runs on your machine from one instance file: the store is a SQLite file, the chat app listens on loopback only, nothing is installed globally, and the code is MIT licensed. The only things that leave are your prompts to the model provider you chose and, if you run a hub, sealed notes it cannot read.

The instance file sets the models, scopes and which components are on; only the store is required. Sources, adapters, retrieval corpora, providers, backends and tools are plugin interfaces, and a local program can stand in as a model provider. The model key lives in the instance keyring, never printed. The core packages import nothing outside Node's standard library and no package has an install script. It needs macOS or Linux, Node 22.13 or newer and an Anthropic API key, and it is young: v1.0.x, not independently audited.
